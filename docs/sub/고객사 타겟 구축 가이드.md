# 고객사 타겟 구축 가이드

> **문서 목적:** 고객사 개발자가 Adobe Target(디지털 인바운드 태깅)을 **웹/앱에 적용하기 위해 필요한 IT 기반 작업 목록**과 단계별 상세·출처를 제공한다.  
> **렌더 기본값:** Form-based **JSON 오퍼** 수신 후 **고객사 FE/네이티브가 자체 렌더**(헤드리스). VEC DOM 자동 변조는 본 가이드 기본 범위가 아니다.  
> **근거 우선순위:** ① Adobe 공식문서 → ② 본 저장소에서 구현·테스트 완료한 샘플 코드 → ③ `docs/sub/Target 구축 사전 질문 체크리스트 관련정보(RFP 포함).html` (배경·용어 참고).  
> **비범위:** 마케팅 활동 설계 전체, 백엔드 API, at.js / 클래식 Mobile Target(`retrieveLocationContent`) 본선.

| 항목 | 값 |
|------|-----|
| 대상 | 고객사 웹/앱 개발 · Data Collection 설정 담당 |
| 표준 경로 | **Web:** AEP Web SDK(`alloy`) · **App:** Edge + Optimize |
| KPI | SDK 초기화 → 개인화 요청 → JSON 오퍼 수신 → 화면 표시 |
| 연관 | `docs/main/01_AEP_SDK_TARGET_TEST_PRD.md` · `docs/report/02_Customer_Config_Guide.md` |

---

## 0. 한 줄 요약

```text
Datastream에 Target이 붙은 Edge Network로
  웹(alloy) / 앱(Edge+Optimize)이 JSON 오퍼를 받아
  고객사 화면 컴포넌트가 렌더한다.
```

Target은 **콘텐츠 결정(decisioning)** 만 담당한다. **그리는 주체 = 고객사 코드**.

## 1. 전체 흐름도 (공통)

```text
[고객사 클라이언트: Web 또는 Native]
        │  HTTPS
        ▼
[ (선택) 1st-party 간판 도메인 ] ──CNAME──▶ Adobe Edge
        │  없으면 기본 edge.adobedc.net 등
        ▼
[ Adobe Experience Platform Edge Network ]
        │  datastreamId / edge.configId
        ▼
[ Datastream — Adobe Target 서비스 ON ]
        ▼
[ Adobe Target ] ── proposition / JSON content ──▶ [고객사 렌더]
```

| 채널 | SDK | 요청 API | Datastream 주입 | 렌더 |
|------|-----|----------|-----------------|------|
| Web | `@adobe/alloy` | `sendEvent` + `decisionScopes` | 코드 `datastreamId` | `renderDecisions: false` 후 JSON 파싱 |
| App | Core + Edge + Edge Identity + Optimize | `updatePropositions` → `getPropositions` | Tags Edge `edge.configId` (Publish) | proposition content → 네이티브 UI |

## 2. 기반 작업 목록 (단계별)

고객사 IT가 **순서대로** 완료할 작업. 각 단계의 상세·출처·샘플은 §3 이후.

| 단계 | 작업 | 담당(일반) | Web | App | 산출물 |
|------|------|------------|-----|-----|--------|
| **S0** | 경로·역할 확정 (헤드리스 JSON / Edge 표준) | 기획·개발 공통 | ✅ | ✅ | 렌더 주체·스코프 합의 |
| **S1** | Datastream 생성 + Adobe Target 서비스 ON | Data Collection | ✅ | ✅ | Datastream ID |
| **S2** | Target Form-based 활동 + JSON 오퍼 + Location(Live) | Target 운영/개발 | ✅ | ✅ | decision scope 문자열 |
| **S3** | Tags 구성 (Web 선택 / App 필수) | Data Collection | 선택 | ✅ | Environment File ID(App) |
| **S4** | 클라이언트 SDK 패키지·초기화 | 앱/웹 개발 | ✅ | ✅ | configure / initialize 성공 |
| **S5** | 개인화 요청 + mbox/파라미터 계약 | 앱/웹 개발 | ✅ | ✅ | proposition 수신 |
| **S6** | JSON 파싱·렌더 컴포넌트 | FE / 네이티브 | ✅ | ✅ | 화면 표시(KPI) |
| **S7** | (선택) 1st-party Edge 도메인(FPC/CNAME) | 인프라·DNS | 선택 | 선택 | `edgeDomain` / `edge.domain` |
| **S8** | 검수·디버그 (Network / Assurance) | QA·개발 | ✅ | ✅ | 수락 체크리스트 통과 |

> **디지털 IB 태깅 관점:** S1~S3는 Adobe 콘솔 기반 작업, S4~S6가 고객사 코드의 핵심 기반 작업이다. 백엔드 서버는 **필수가 아니다**(클라이언트 → Edge 직결).

## 3. 단계별 상세

### S0. 경로·역할 확정

**해야 할 일**

1. 표준 경로 채택: **Web = alloy(W-A)** · **App = Edge+Optimize(M-A)**.  
2. 오퍼 형태 = **JSON 헤드리스** (고객사 컴포넌트 렌더).  
3. 개발 경계 합의: Target 활동/오퍼 작성 vs 클라이언트 SDK·렌더 코드.

**가이드**

- “SDK 구축 = 서버사이드”가 **아님**. alloy / Mobile SDK는 클라이언트사이드.  
- 클래식 at.js / Mobile Target 확장은 본 가이드 비권장(마이그레이션·스택 혼선).

### S5. 개인화 요청 (JSON 오퍼 Fetch)

#### Web 알고리즘

```text
sendEvent(
  renderDecisions: false,          // 헤드리스 — SDK DOM 자동적용 OFF
  personalization.decisionScopes,  // Target Location과 동일
  data.__adobe.target.*            // (선택) mbox 파라미터
)
→ response.propositions[]
→ items[].data.content  (JSON)
```

```typescript
// 샘플: web/src/03_target/web_target_service.ts
const rawResponse = await alloy("sendEvent", {
  renderDecisions: false,
  personalization: {
    decisionScopes: [decisionScope],
    sendDisplayEvent: false,
  },
  xdm: {
    eventType: "decisioning.propositionFetch",
    web: { webPageDetails: { name: "aep-web-sdk-target-test" } },
  },
  data: {
    __adobe: { target: { testNum } }, // Custom Audience 매칭 예
  },
});
```

**출처:** [sendEvent](https://experienceleague.adobe.com/en/docs/experience-platform/web-sdk/commands/sendevent/overview) · [Setup Target](https://experienceleague.adobe.com/en/docs/platform-learn/implement-web-sdk/applications-setup/setup-target)

#### App 알고리즘

```text
clearCachedPropositions (필요 시)
→ updatePropositions(scopes, xdm?, data?)
→ onSuccess / onPropositionUpdate
→ (폴백) getPropositions(scopes)
→ Map/객체 propositions → content JSON
```

```typescript
// 샘플: app/src/03_target/app_target_service.ts
const scopes = [new DecisionScope(decisionScope)];
const data = { __adobe: { target: { testNum: String(testNum) } } };

Optimize.updatePropositions(
  scopes,
  undefined,
  data,
  (propositions) => { /* cache filled */ },
  (error) => { /* handle */ }
);
const cached = await Optimize.getPropositions(scopes);
```

**가이드 (본 프로젝트 함정)**

- `updatePropositions` 콜백 미수신 → timeout 가드 + `onPropositionUpdate` 병행(본 레포).  
- `data.__adobe.target` 은 **요청(mbox) 파라미터** (`profile.` / `entity.` 접두사 없음).  
- Fetch마다 audience 매칭 파라미터를 보내야 하면 **항상** 전송(빈 요청만 보내지 말 것).

**출처:** [Offer Decisioning and Target](https://developer.adobe.com/client-sdks/edge/adobe-journey-optimizer-decisioning/)

### S6. JSON 파싱 · 렌더 (핵심 개발 스코프)

#### 렌더 알고리즘 (권장)

```text
INPUT: propositions
FOR each proposition:
  FOR each item:
    content ← item.data.content | item.content | getContent()
    IF content is string:
      content ← JSON.parse (필요 시 이중 parse)   // Target이 stringify 하는 경우
    IF content is array:
      각 entry를 OfferPayload로 취급
    ELSE:
      content를 OfferPayload로 취급
    UI:
      type === "event-popup" → 모달
      else → 카드/배너 등 고객사 컴포넌트에 title/body/… 바인딩
```

#### 타입 계약 샘플

```typescript
// web|app …/03_target/*_target_types.ts
export interface OfferPayload {
  type?: string;
  title?: string;
  body?: string;
  buttonText?: string;
  [key: string]: unknown;
}
```

#### 디코드 샘플 (문자열/이중 JSON 대응)

```typescript
// web/src/03_target/web_target_service.ts · app/src/03_target/app_target_service.ts
export function decodeOfferContent(content: unknown): unknown {
  let value = content;
  if (typeof value === "string") {
    try {
      value = JSON.parse(value);
      if (typeof value === "string") {
        value = JSON.parse(value);
      }
    } catch {
      return { body: content };
    }
  }
  return value;
}
```

#### UI 바인딩 샘플

- Web: `web/src/04_ui/web_ui.ts` — `renderOffers` / `showEventPopup`  
- App: `app/src/04_ui/AppScreen.tsx` — 오퍼 카드 + `Modal`(event-popup)

**가이드**

- KPI는 “Assurance 연결”이 아니라 **오퍼 JSON이 화면에 보이는 것**.  
- VEC/HTML 자동 적용(`renderDecisions: true`)과 혼용하지 말 것 — 본 가이드는 헤드리스만.

**출처**

- [JSON Offer](https://experienceleague.adobe.com/en/docs/target/using/experiences/offers/create-json-offer)
- 체크리스트 HTML §C 오퍼/렌더링(JSON)

### S7. (선택) 1st-party Edge 도메인

**해야 할 일**

1. 간판 호스트 결정 → Adobe FPC/Managed Certificate 절차.  
2. DNS **CNAME**(간판 → Adobe 호스트). 고객 서버 IP로 A 레코드하지 않음.  
3. SDK에만 간판 주입.

| SDK | 키 |
|-----|-----|
| Web | `edgeDomain` |
| App | Tags Edge Domain 또는 `edge.domain` |

**가이드:** Dev 검증은 Adobe 기본/샌드박스 Edge 도메인으로 가능. FPC는 조직 정책·무과금 요건 시.

**출처:** [edgeDomain](https://experienceleague.adobe.com/en/docs/experience-platform/web-sdk/commands/configure/edgedomain) · [Edge Network domain (Mobile)](https://developer.adobe.com/client-sdks/edge/edge-network/)

## 4. 채널별 시퀀스 (오케스트레이션)

### Web

```text
loadWebConfig
  → initWebSdk (alloy configure)
  → [사용자 Fetch]
  → fetchTargetOffers (sendEvent)
  → parsePropositions / decodeOfferContent
  → renderOffers + (event-popup) showEventPopup
```

진입점: `web/src/main.ts`

### App

```text
loadAppConfig
  → initMobileSdk (initializeWithAppId + OPT_IN)
  → waitForEdgeReady (ECID)
  → [사용자 Fetch]
  → fetchTargetOffers (updatePropositions → getPropositions)
  → parsePropositionMap / parseEventPopup
  → AppScreen 렌더
```

진입점: `app/App.tsx`
